# SST Dynamics - Forged Private Key (Crypto)

## Challenge summary
The service implements a custom tropical-matrix signature scheme and exposes a menu:

1. View public key `T` (8x8)
2. View signed orders
3. Submit private key `(X, Y)` with dimensions `(8x7)` and `(7x8)`

To get the flag, it only checks:

- entries are in `[0,255]`
- dimensions are correct
- `X * Y == T` under tropical multiplication

It does **not** verify that `(X, Y)` is the original keypair generated by `keygen()`.

## Core vulnerability
This is a classic authentication flaw: the verifier accepts **any valid factorization** of the public key, instead of binding to the unique original secret (which is not unique in this algebra anyway).

So the task reduces to:

> Find any matrices `X, Y` such that `T = X * Y` in min-plus (tropical) algebra.

No signature forgery or timestamp manipulation is needed.

## Tropical multiplication used
For `X` of shape `8x7` and `Y` of shape `7x8`:

`(X * Y)[i][j] = min_k ( X[i][k] + Y[k][j] )`

Thus for every `(i,j)` with target value `T[i][j]`, constraints are:

- `X[i][k] + Y[k][j] >= T[i][j]` for all `k`
- for at least one `k`: `X[i][k] + Y[k][j] == T[i][j]`

Also all variables are bounded to `[0,255]`.

## Solver approach
Use Z3 with integer variables:

- `x_{i,k}` for `X`
- `y_{k,j}` for `Y`

Add all constraints above, solve once, submit model back to option `3` as JSON.

This efficiently returns a forged private key accepted by the server.

## Exploit script (single-shot)
```python
import socket, json, re
from z3 import Int, Solver, Or

HOST, PORT = "40.66.60.171", 4244

s = socket.create_connection((HOST, PORT), timeout=10)
buf = b""

def recv_until(token=b"> "):
    global buf
    while token not in buf:
        d = s.recv(4096)
        if not d:
            break
        buf += d
    out = buf
    buf = b""
    return out.decode(errors="ignore")

# banner
recv_until(b"> ")

# get public key
s.sendall(b"1\n")
text = recv_until(b"> ")
m = re.search(r"\n(\[\[.*\]\])", text, re.S)
T = json.loads(m.group(1))

M_DIM, N_DIM, K_DIM = 8, 8, 7

x = [[Int(f"x_{i}_{k}") for k in range(K_DIM)] for i in range(M_DIM)]
y = [[Int(f"y_{k}_{j}") for j in range(N_DIM)] for k in range(K_DIM)]

sol = Solver()

for i in range(M_DIM):
    for k in range(K_DIM):
        sol.add(x[i][k] >= 0, x[i][k] <= 255)

for k in range(K_DIM):
    for j in range(N_DIM):
        sol.add(y[k][j] >= 0, y[k][j] <= 255)

for i in range(M_DIM):
    for j in range(N_DIM):
        sums = [x[i][k] + y[k][j] for k in range(K_DIM)]
        for expr in sums:
            sol.add(expr >= T[i][j])
        sol.add(Or(*[expr == T[i][j] for expr in sums]))

assert str(sol.check()) == "sat"
model = sol.model()

X = [[model.evaluate(x[i][k]).as_long() for k in range(K_DIM)] for i in range(M_DIM)]
Y = [[model.evaluate(y[k][j]).as_long() for j in range(N_DIM)] for k in range(K_DIM)]

# submit forged key
s.sendall(b"3\n")
recv_until(b"> ")
s.sendall((json.dumps({"X": X, "Y": Y}) + "\n").encode())

print(s.recv(8192).decode(errors="ignore"))
```

## Result
Flag recovered:

`THC{tr0p1c4l_f4ct0r1z4t10n_1s_NP_h4rd_but_wh0_c4r3s}`

## Why this works (short)
The scheme is not broken through signatures; the implementation logic is. The check is equivalent to proving knowledge of *a* factorization, not *the* secret factorization. Since many factorizations may exist, SMT can produce one and bypass authentication.
